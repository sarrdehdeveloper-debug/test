# Zodiac Blend — web (Next.js)

Public site (English + Arabic/RTL) and, later, the admin dashboard of **Zodiac Blend**
("Two Traditions. One Truth."). All data comes from the FastAPI backend (`../backend`); the API
contract is `../docs/ARCHITECTURE.md` §5–6.

> **This is Next.js 16.3** (App Router, Turbopack, React 19.2). Several APIs differ from older
> versions — read `node_modules/next/dist/docs/` before using an API you have not used here.
> Middleware is now `src/proxy.ts`; error boundaries receive `retry()`; `next/root-params` gives the
> locale to any Server Component; `PageProps<"/[locale]/x">` / `LayoutProps` are global types
> (generated by `next typegen`, `next dev` or `next build`).

## Quick start

```bash
npm ci
npm run dev          # http://localhost:3000 (redirects to /en or /ar)
npm run build        # production build (works with the API down: fallback content)
npm start            # serve the build
npm run lint         # ESLint (next config)
npx tsc --noEmit     # type check (run `npm run typecheck` on a fresh clone: it runs next typegen first)
npm test             # Vitest: unit + component tests
npm run format       # Prettier
npm run brand:assets # regenerate PNG/ICO brand assets from ../brand/logo.svg (sharp)
```

## Routing and i18n

- Locales: `en` (default) and `ar` (RTL), always prefixed: `/en/...`, `/ar/...`. `src/proxy.ts`
  redirects `/` and any locale-less page path using the `NEXT_LOCALE` cookie / `Accept-Language`.
- **New public page** → `src/app/[locale]/(site)/<route>/page.tsx` (routes listed in ARCHITECTURE §5:
  `/free`, `/reading`, `/order/[id]`, `/report/[id]`, `/checkout/fake`, `/offers[/slug]`,
  `/blog[/slug]`, `/library[/slug]`, `/privacy`, `/terms`, `/contact`). The nav already links to them.
  ```tsx
  export async function generateMetadata({ params }: PageProps<"/[locale]/free">) {
    const { locale } = await params;
    const c = await getSiteContent(locale);
    return pageMetadata({ locale, path: "/free", title: c.t("free.intro.title"), description: c.t("free.intro.body") });
  }
  export default async function FreePage({ params }: PageProps<"/[locale]/free">) {
    const { locale } = await params;
    const t = await getTranslations("form");          // next-intl/server
    ...
  }
  ```
  Private pages (order, report, checkout) pass `noIndex: true` to `pageMetadata` (robots.ts already
  disallows them).
  The `(site)` group does not change URLs. Its `loading.tsx` makes request-time pages stream, so a
  `notFound()` there (e.g. unknown blog slug) is sent with status 200 plus `noindex` (Next.js
  behaviour); only `[...rest]` sits outside the group, so unknown URLs keep a real 404.
- **Links**: always import `Link`, `redirect`, `useRouter`, `usePathname` from `@/i18n/navigation`
  and write hrefs **without** the locale (`<Link href="/free">`); the current locale is added.
  `<Button href="/free">` does the same; external URLs (`https://`, `mailto:`) become plain `<a>`.
  URLs from the CMS (offer `cta_url`, e.g. the seeded `/reading`) go through `toSiteHref()` first,
  which also strips a stored `/en` or `/ar` prefix so visitors stay in their language.
- **Messages**: add every new key to **both** `messages/en.json` and `messages/ar.json` (the test
  suite fails on missing keys, empty strings or mismatched ICU arguments/tags). Keys are typed
  (`src/global.d.ts`), so typos fail `tsc`. Server Components use `getTranslations` / plain
  `useTranslations` in sync components; Client Components use `useTranslations`, and their namespace
  must be listed in `src/i18n/client-messages.ts` (only those are sent to the browser). Available
  namespaces: `meta, nav, footer, common, form (labels, placeholders, hints, validation, combobox),
errors, errorPage, notFound, zodiac (signs, animals, elements, polarity, labels), orderStatus,
orderStatusDescription, offers, blog, home, content`.
- **RTL**: use logical utilities only (`ms-/me-/ps-/pe-/start-/end-/text-start/border-s`), never
  `ml-/mr-/left-/right-/text-left`. Mirror directional icons with `rtl:-scale-x-100` (`ArrowIcon`
  does). Put `dir="ltr"` on emails, phone numbers, codes, prices and native date/time inputs.
  Arabic uses Latin digits (`ar-u-nu-latn`, see `intlLocale()`); format with `formatMoney()` /
  `formatDate()` from `src/lib/format.ts`. The brand name stays Latin ("Zodiac Blend") in Arabic.

## Fetching from the API

**Server Components** (pages, layouts, `generateMetadata`) — `src/lib/api/server.ts`:

```ts
const data = await apiGet<Paginated<PostSummary>>("/blog", {
  locale, query: { page: 1, page_size: 9 }, revalidate: 120, tags: [CACHE_TAGS.blog],
});
if (!data) return <FallbackOrNothing />;          // API down / 5xx / timeout -> null, never throws
const res = await apiGetResult<PostOut>(`/blog/${slug}`, { locale });
if (!res.ok && res.error.isNotFound) notFound();  // tell 404 from "API down"
```

- Calls `API_BASE_URL` directly (not through `/api`), 5 s timeout, `revalidate` default 60 s
  (`0` = per request). Pages stay static/ISR: `export const revalidate = 60` like the home page.
- The API is **not** running during `next build`; every page must render fallback content.
- Never send personal data through cached GETs; order/report pages fetch on the client.

**Client Components** — `src/lib/api/client.ts` (relative `/api/v1/...`, same-origin cookies):

```ts
try {
  const result = await api.post<FreeReadingResult>("/free-reading", body);
  const order = await api.get<OrderStatusOut>(`/orders/${id}`, {
    headers: { "X-Order-Token": token },
  });
} catch (err) {
  const message = useApiErrorMessage()(err); // localized (errors.*), from the hook in the component
  if (isApiError(err)) err.fieldErrorMap(); // 422 validation_error -> { field: message }
  ambiguousTimeOptions(err);
  suggestedTime(err);
  discountErrorReason(err); // order-form helpers
}
```

`ApiError` has `status`, `code` (API code or `network` / `server_error` / `http_error`),
`details`, `retryAfter`, `isRateLimited`, `isNotFound`. All request/response shapes are in
`src/lib/types.ts` (City, Country, FreeReadingResult, FreeSigns, Quote, OrderCreate, OrderCreated,
OrderStatusOut, OfferOut, PostSummary, PostOut, SeriesOut, PublicConfig, SiteContent,
ApiErrorBody, …) plus enums (`WESTERN_SIGNS`, `CHINESE_ANIMALS`, `ELEMENTS`, `ORDER_STATUSES`,
`FINAL_ORDER_STATUSES`). The order access token goes to `localStorage[orderTokenStorageKey(id)]`
(`src/lib/site.ts`).

**Public settings**: `const config = await getPublicConfig()` → price, currency, access hours,
`payment_provider`, `min_birth_date` (falls back to `DEFAULT_PUBLIC_CONFIG`, $29).

## Editable site copy (CMS)

```tsx
const c = await getSiteContent(locale); // src/lib/content.ts (Server Components)
c.t("home.hero.title"); // text
c.lines("home.plans.free.features"); // `lines` keys -> string[]
<div className="prose-zb" dangerouslySetInnerHTML={{ __html: c.html("legal.terms.body") }} />; // markdown keys
```

Precedence per key: API value → `content.<key>` in messages → fallback argument. The `content.*`
defaults mirror the backend seed (`backend/app/seed/site_content.py`), except the legal bodies,
which show a "temporarily unavailable" notice rather than a possibly outdated policy.
**Adding a key**: add it to `backend/app/content/keys.py`, `src/lib/content-keys.ts` and
`content.*` in both message files — `npm test` checks all three agree. Pass `content` down to
child sections as a prop (see `src/components/home/*`).

  Inside components use `text-fg`, `text-muted`, `text-accent`, `bg-surface`, `bg-card`,
  `border-line`, `text-ornament` so they read correctly on light **and** dark bands.
- **Utilities**: `bg-gold-gradient` (#E9C77B→#C78933→#A46F26), `bg-gold-soft-gradient` (behind
  dark button text), `text-gold-gradient`, `rule-gold` (fading hairline), `eyebrow` (small caps
  label), `bg-night-sky` (navy with celestial glow), `border-gold-gradient`, `prose-zb` (API HTML),
  `animate-twinkle|orbit|orbit-reverse|fade-up`, shadows `shadow-card|lift|glow`.
- **Accessibility**: gold text only on navy or at large sizes (use `text-accent`/`gold-deep` on
  light); every interactive element keeps the global `:focus-visible` ring (`--tone-focus`);
  animations stop under `prefers-reduced-motion` (spinners slow down instead); design mobile-first
  and check 360 px; the page must not scroll horizontally.
- **`cn()` does not merge classes**: a `className` only overrides a component's own utility for the
  same property if Tailwind emits it later. Override display with variants: hide a `<Button>`
  (base `inline-flex`) with `max-md:hidden`, not `hidden md:inline-flex`.

## Security

- `next.config.ts` sets CSP (`default-src 'self'`, images `self data: blob: https:`, no third-party
  scripts — Stripe Checkout is a top-level redirect; `form-action` allows checkout.stripe.com;
  `frame-ancestors 'none'`), `Referrer-Policy: strict-origin-when-cross-origin`,
  `X-Content-Type-Options: nosniff`, `X-Frame-Options`, COOP, Permissions-Policy, HSTS.
  Adding a third-party script/iframe/connect target means updating the CSP there.
- `/api/*` is rewritten to FastAPI. Next.js would forward a browser-supplied `X-Forwarded-For`
  unchanged and adds none of its own, while the API rate-limits on its first entry. `src/proxy.ts`
  therefore replaces it with one address (`src/lib/forwarded.ts`) and drops `X-Real-IP`. Set
  `TRUSTED_PROXY_HOPS` to the number of reverse proxies in front of Next.js (each must append the
  address it saw, e.g. nginx `$proxy_add_x_forwarded_for`). With `0`, a client that sends its own
  header can still pick its address, so production should run behind a reverse proxy, and the API
  must not be reachable directly.

## Admin dashboard conventions

`/admin` has its **own root layout** (`src/app/admin/layout.tsx`: `<html lang="en" dir="ltr">`,
fonts, `globals.css` + `admin.css`, `robots: noindex` for every page). It is outside the locale
routing (`src/proxy.ts` skips `/admin`): **English UI, plain strings, no next-intl**, and no
`@/i18n/navigation` / `ui/Button` links (use `next/link`, `AdminButtonLink`). Look: ivory page,
white panels with `stone-*` hairlines, navy sidebar, gold accents; Inter body, Cormorant `h1`.

```
src/app/admin/layout.tsx            root layout (metadata title template "%s · Zodiac Blend Admin")
src/app/admin/login/                /admin/login: email + password, then TOTP step (mfa_required)
src/app/admin/(dashboard)/layout.tsx AdminAuthProvider + AdminShell around every signed-in page
src/app/admin/(dashboard)/page.tsx  overview (managers: KPIs, recent orders; editors: welcome)
src/app/admin/(dashboard)/account/  profile, password change, two-factor setup / disable
src/app/admin/(dashboard)/<route>/  one folder per section (placeholders use <ComingSoon>)
src/lib/admin/                      api, types, hooks, format, errors, toast, nav, roles, …
src/components/admin/               shared components (import from "@/components/admin")
```

**Auth & roles.** `AdminAuthProvider` loads `GET /auth/me` once; `useAdminAuth()` gives
`{user, status, refresh, setUser, logout, can}` (`can("manager")`, `can("owner")`; owner ⊃ admin ⊃
editor, "manager" = owner/admin). Any admin request answering **401** redirects to
`/admin/login?next=<path>` (only same-origin `/admin` paths are honoured, `safeNextPath`). The route
map with each section's minimum role lives in `src/lib/admin/nav.ts` (`ADMIN_NAV`): the sidebar is
built from it **and** `AdminShell` shows the "no permission" state for pages above the user's role
(longest matching prefix), so a new page under an existing section is guarded automatically. Use
`<RequireRole role="owner" fallback={null}>` for parts of a page; a **403** from the API renders
`<ErrorState>` as the same "no permission" state.

**Adding a page** (e.g. `/admin/offers`): replace the placeholder `page.tsx` with a Server Component
that only exports metadata and renders a client view next to it:

```tsx
// src/app/admin/(dashboard)/offers/page.tsx
export const metadata: Metadata = { title: "Offers" };
export default function OffersPage() {
  return <OffersView />;
}
```


A brand-new top-level section also needs an entry in `ADMIN_NAV` (label, icon, `access`).
`AdminShell` wraps pages in `<Suspense>`, so `useSearchParams`/`useUrlParams` need no extra boundary.

**Data (`src/lib/admin/`).**

- `adminApi.get/post/put/patch/delete/upload(path, …)` — paths relative to `/api/v1/admin`
  (`"/api/v1/public-config"` style full paths also work); same-origin with the session cookie;
  `X-ZB-Admin: 1` on every non-GET; JSON in/out; 204 → `undefined`; `upload(path, formData, {onProgress})`
  uses XHR for progress. Failures throw `AdminApiError` (`status, code, message, details, fields`
  (`{"translations.en.title": msg}` from 422 `details.fields`), `retryAfterSeconds`, `isUnauthorized`,
  `isForbidden`, `isValidation`, `isConflict`, `isNotFound`). Pass `{redirectOn401: false}` to handle a
  401 yourself.
- `useAdminQuery<T>(path | null, {query, enabled, refreshInterval, keepPreviousData})` →
  `{data, loading (first load), fetching, isPlaceholder, error, refetch(), setData(), updatedAt}`;
  changing `query` refetches and keeps the previous data (no layout shift).
- `useAdminMutation(fn, {successMessage, errorMessage, onSuccess, onError})` → `{mutate (never throws),
mutateAsync, pending, error, fieldErrors, reset}`; toasts success/errors (no toast on 401;
  `errorMessage: false` or a function returning `null` to show errors inline instead).
- `adminErrorMessage(err)` / `adminFieldErrors(err)` (English text for every backend code),
  `toast.success|error|info|warning(title, {description, action})`, `useAdminLocales()` (content
  locales from public-config), `useDebouncedValue`, `useUrlParams`.
- `types.ts` mirrors **every** admin request/response (auth, users, audit, orders, jobs, dashboard,
  prompts, site content, free readings, offers, discounts, library, blog, media, settings).
- `format.ts`: `formatMoney(cents, cur)`, `formatDateTime`, `formatDate`, `formatTime`,
  `formatRelative`, `formatBytes`, `humanize`, `shortId`, `isoToLocalInput`/`localInputToIso`,
  `centsToInput`/`parseMoneyInput`. Dates are shown in the admin's own time zone.

**Components** (`@/components/admin`, all documented with JSDoc): `PageHeader` (title, description,
actions, breadcrumbs, badge) · `Panel` (white card: title, actions, footer, `padding="none"` for tables)

**Rules.** Arabic content controls get `lang="ar" dir="rtl"` (`fieldProps`; `admin.css` switches to
Noto Naskh/Amiri) while labels stay English/LTR; use logical utilities (`ms-`, `ps-`, `start-`)
anyway. Errors inside a modal are shown inline (toasts sit below the modal backdrop). After content
edits call `revalidateTag(CACHE_TAGS.x, "max")` from a Server Action so the public pages refresh at
once. Test logins live in the shared dev DB (owner/editor, see the task brief): never change their
password or MFA; create your own admin (`POST /admin/users`, `example.com` email) for account flows
and deactivate it afterwards. Note: open the dev server as **`http://localhost:3000`** for browser
checks — Next blocks its dev resources (HMR) for other hosts such as `127.0.0.1` unless they are in
`allowedDevOrigins`, and pages opened that way never hydrate.

tests start with `// @vitest-environment jsdom`, wrap client components that translate in
`<NextIntlClientProvider locale="en" messages={messages}>`, and mock `@/i18n/navigation` when
they render links (see `src/components/ui/Button.test.tsx`). `src/i18n/messages.test.ts` guards
message parity and the site-content key list.
